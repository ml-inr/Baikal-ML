# doc/ — что здесь лежит

Указатель по документации проекта. Состояние на 2026-09-06.

Документы делятся на три класса с разной судьбой при рефакторингах. Это деление —
не формальность: оно объясняет, какие файлы можно править свободно, а какие нельзя.

---

## Справочники по данным

Описывают **формат и происхождение данных**, а не расположение кода. От перемещения
файлов не устаревают. Правятся только тогда, когда меняются сами данные.

| Файл | О чём |
|---|---|
| [hdf5_format.md](hdf5_format.md) | разметка каждого HDF5: источники, выходы инференса, энергетический компаньон |
| [mc_provenance.md](mc_provenance.md) | откуда взят MC: генератор → `.dat` → `mcread` → `.wout` → `bexport-mc` → ROOT → h5; какая продукция какому сезону соответствует |
| [mc_binary_formats.md](mc_binary_formats.md) | пословная разметка `.dat` / `.wout`, сверенная с ROOT |
| [mc_energy_truth.md](mc_energy_truth.md) | какая энергетическая истина существует: три случая `fMuonEnergy`, таргеты из цепочки взаимодействий, пределы применимости |
| [hdf5_energy_truth.md](hdf5_energy_truth.md) | схема компаньон-файла с энергетической истиной |
| [energy_twin_plan.md](energy_twin_plan.md) | план сборки компаньона по стадиям |
| [reco_quality_cuts.md](reco_quality_cuts.md) | рекомендованные BARS-каты: где лежит каждая величина, смешанные единицы, незаполненные поля, известные дефекты |
| [track_fit_alike_bars.md](track_fit_alike_bars.md) | порт фита BARS: что воспроизведено и с чем сверено, где взять DQM-маску каналов, что расходится и почему |

**Прежде чем доверять утверждению об единицах или семантике поля — прочтите
`mc_provenance.md`.** Комментарии в BARS расходятся с данными.

## Журнал утверждений

[claims_log.md](claims_log.md) — каждое фактическое утверждение, на которое опирается
проект, со своим статусом: `verified` / `consistent` / `assumed` / `refuted`.

Проверяйте здесь, прежде чем на что-то опереться, и обновляйте, когда статус меняется.
Правила, по которым утверждение получает статус, — в разделе «Verifying claims» в
[../AGENTS.md](../AGENTS.md).

## Учебные материалы

Конспекты для разбора механизмов — ни справочники по данным, ни журнал утверждений.
Каждый лежит в своей папке вместе со скриптами, которые строят иллюстрации и сам PDF:
номера и рисунки воспроизводимы, ничего не собирается «руками».

| Материал | О чём |
|---|---|
| [learning/dann_encoder_shortcut/dann_encoder_shortcut.pdf](learning/dann_encoder_shortcut/dann_encoder_shortcut.pdf) | почему энкодер обходит дискриминатор в DANN: минимаксная игра и её равновесие, геометрия обхода на низкоразмерных примерах, метры инвариантности, лечение (ансамбль, BSP, свежесть экзаменатора) и её пределы. Сборка — `build_pdf.py`, рисунки — `figures.py` |
| [learning/dann_encoder_shortcut/toy_domain_hiding.ipynb](learning/dann_encoder_shortcut/toy_domain_hiding.ipynb) | то же явление руками: синтетика на CPU, два режима — линейный энкодер (видно вращение и карусель) и нелинейный (критик устойчиво слеп, линейная проба слепнет вместе с ним, а нелинейная видит домен). Считается за ~4 минуты, выводы вшиты в файл |
| [learning/dann_encoder_shortcut/rotation_measurement_3d.ipynb](learning/dann_encoder_shortcut/rotation_measurement_3d.ipynb) | аналитическое дополнение: 3D-данные, **четыре облака** (оба класса в обоих доменах), нелинейные и энкодер, и дискриминатор. Измеряется: остаточный сдвиг домена по каждому классу, маргинальные пробы против **условных** (внутри класса), оракульная точность на цели, сдвиг класс-скора. С комиксом (9 панелей) и разбором «честное выравнивание против подмены классов». Плюс сопутствующий `toy_domain_hiding.ipynb` — трёхоблачная версия, где класс-лосс ничего не знает о цели и потому возможно прятки |

## Чего здесь нет

Карты кода и описания трактов. Они в [../AGENTS.md](../AGENTS.md) — там же данные,
канонические модели и команды запуска. Правила написания кода — в
[../conventions.md](../conventions.md).

Документы, описывавшие структуру кода и план из восьми итераций (`vision.md`,
`data_format.md`, `tasklist.md`, `workflow.md`, `PROJECT_STATUS.md`,
`iteration3_summary.md`, `enhanced_training_features.md`, `idea.md`), выведены в
`archive_tracked/`. Они устарели не по частям, а целиком: нумерация итераций
закончилась на седьмой, после чего были SNGP, fine-tuning, анализы избытка и `reader`,
которые в неё не укладываются.
