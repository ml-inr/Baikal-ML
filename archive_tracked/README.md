# archive_tracked/

Код, выведенный из активного дерева, но сохраняемый в истории git.

## Зачем отдельно от `archive/`

В репозитории два архивных каталога, и разница между ними существенная:

| | `archive/` | `archive_tracked/` |
|---|---|---|
| Под версиями | нет (кроме исходников, см. `.gitignore`) | да |
| Назначение | старые черновики и эксперименты | код, снятый с эксплуатации по решению из `doc/AUDIT.md` §8.2 |

## Правило `.gitignore`

Оба каталога работают по принципу **default-deny**: отслеживаются только
`.py`, `.sh`, `.yaml`, `.yml`, `.md`, `.ipynb`. Файл данных, положенный сюда,
останется вне git независимо от расширения — включая `.dat`, `.wout`, `.tar`,
`.bin`, для которых отдельных правил в `.gitignore` нет.

Проверить, что именно попадёт под версии:

```bash
git check-ignore -q --no-index archive_tracked/<путь> && echo ИГНОР || echo TRACK
```

Судить по коду возврата, а не по выводу `-v`: с флагом `-v` печатаются и
отрицающие правила, поэтому наличие вывода не означает, что файл игнорируется.

## Что здесь лежит

Каждое перемещение — отдельный коммит со ссылкой на номер решения (Q4, Q5, …)
из `doc/AUDIT.md` §8. Имена модулей при перемещении не менялись.
