# da_onset_geometry — включение DA-игры крупным планом (v3)

Диагностика (запрос владельца): с чистого чекпойнта **эпохи 5** (λ ещё выключена; прогон
`261013_1823_..._dlr1e-2_lam0p01_delay8_s42`) дообучаем **5000 батчей** (~5 эпох на 1/10)
с разными (λ, D-LR) и следим за геометрией пространства фич **по батчам** на фиксированном
наборе из 16 008 held-out событий (`data_manager/probe_sample/probe_sample.npz`).

Шаг обучения — дословная копия `train_epoch` тренера (set_lambda → класс → домен → три
step). Каждая рука — **отдельный процесс** (партия `run_grid.sh`), все — с одного
чекпойнта и одного порядка батчей (посев 42 перед каждой эпохой; shuffle идёт из
глобального RNG, дропаут детерминирован по батчам).

**Правила (уточнение владельца 15.10):** ДОМЕННЫЕ метрики — только игровая конструкция:
источник = MC (μ+ν вперемешку, половинный z-flip, фиксированный сид 42), цель = exp,
удвоенная зеркалом. КЛАССОВЫЕ метрики — на **чистых** событиях: классификатор в обучении
видит source-батчи **без z-флипа** (rotation в плоскости x-y и малый координатный шум
включены, вертикальную ось не ломают; afterpulse везде выключена). Чистые доменные
метрики v2 убраны в `v2_400_batches/`.

**Партия:** 16 рук = λ ∈ {0.001, 0.003, 0.01, 0.03, 0.1} × D-LR ∈ {1e-3, 1e-2, 3e-2}
+ контроль λ=0. Время на руку ~3–4.5 ч (по 4 процесса на карту: cuda:1 P100, 2/3 Ada, 5 A100).

## Метрики (колонки CSV)

| колонка | период | что значит |
|---|---|---|
| `cls_loss`, `dom_loss`, `dom_acc` | каждый батч | лоссы и точность живого критика на его же доменных батчах (0.5 = мёртв; «кто выигрывает») |
| `d_ratio`, `ang_d` | 10 | сжатие и поворот вектора центроидов tgt−src против t0 |
| `auc_dom` | 10 | AUC лучшей линейной домен-оси (Fisher Σ⁻¹Δμ, **in-sample**) — пересечение |
| `cov_ratio` | 10 | tr Σ_tgt / tr Σ_src — масштаб (форма) |
| `w0_game` | 10 | AUC читателя, обученного на t0, на текущей игре (линейка сдвига) |
| `auc_cls` | 10 | AUC класс-оси (μ против ν, **чистые**, как в обучении) |
| `cos_cls_pca1` | 10 | класс-ось (чистые) против PCA1 чистого облака |
| `cos_dom_cls` | 10 | домен-ось (игра) против класс-оси (чистые) |
| `cos_dom_pca1` | 10 | домен-ось (игра) против PCA1 игрового облака |
| `fresh_game` | 50 | свежий читатель, логрег **2-fold** — честный метр изъятия |
| `cos_freshdom_{cls,w0,pca1}` | 50 | куда смотрит свежая домен-ось (к класс-оси, к w₀, к PCA1) |
| `pca_angle` | 50 | старший главный угол PCA-8 против t0 (поворот подпространства) |

## Честность

- `auc_dom` / `auc_cls` — **in-sample** (направление и оценка на одной выборке): 128
  параметров против ~16k событий, смещение мало и одинаково по батчам — для ЭВОЛЮЦИИ,
  не для абсолютного вердикта.
- `fresh_game` — 2-fold, честен. `w0_game` — честен (читатель обучен на t0). `dom_acc` —
  на тренировочных батчах руки (1/10), не на пробе.
- Проба невзвешенная (веса событий в диагностике не участвуют).

## Запуск

```bash
bash inference/nu_classifier/analysis/da_onset_geometry/run_grid.sh          # вся партия
python .../monitor_onset.py --lam 0.01 --dlr 0.01 --n-batches 5000 --device cuda:2  # одна рука
python .../monitor_onset.py --plot-only                                       # картинка из CSV
```

## K-шаги критика (n_critic)

`--k-steps K` (идея владельца 15.10): K−1 шагов критика на отсоединённых фичах
(`get_features` под `no_grad`, энкодер не трогаем) + финальный шаг с графом — градиент
энкодера один раз, от «догнавшего» критика. K=1 — прежний путь. Партии:
`run_grid_k.sh` (λ=0.01: K=5, 10) и `run_grid_k_lam0p1.sh` (λ=0.1: K=3, 5, 10);
CSV с суффиксом `_k<K>`, сравнение с K=1 того же λ из партии v3.
Сводка семьи — `--plot-k` → `da_onset_k_family.png` (честный метр, живой критик, w₀).

## Накопление градиентов игры (--accum)

`--accum N` (идея владельца 16.10): градиенты игры (критик + λ-часть энкодера) копятся
N батчей и применяются раз в N (усреднение /N); классовая ветка учится каждый батч как
обычно, отдельным шагом энкодера; внутренние K−1 адаптационных шагов критика —
немедленные (они «догоняние», не «шаг обучения»). В accum-режиме порядок: класс
(forward/backward/step) → игра (адаптация → накопление финального градиента); при
accum=1 — прежний путь (класс и игра в один backward). Партия: `run_grid_accum.sh`
(чемпион K=10 × N=5, 10); CSV с суффиксом `_a<N>`.

## Файлы

- `monitor_onset.py` — генератор (одна рука на вызов; `--plot-only` собирает картинку).
- `run_grid.sh` — лаунчер партии (16 рук, разнос 60 с).
- `da_onset_geometry.png` — сводка 2×4 (λ — цвет, dlr — стиль линии; контроль серый).
- `onset_<рука>.csv`, `log_<рука>.log` — per-batch метрики и прогресс руки.
- `v2_400_batches/` — архив v2 (400 батчей, смешанные чистые/игровые метрики).
