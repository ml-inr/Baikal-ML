# small_model_critic_diag — почему у маленькой модели критик стоял на 0.53

Замеры 2026-10-10 на чекпойнте эпохи 0 прогона
`trained_models/classifier/261010_1642_da_nu_classifier_exp_full_E1_small_d64_l2_lin`
(энкодер d=64, 2 слоя; критик линейный, 65 параметров).

Вопрос: к концу эпохи 0 in-game критик на случайном уровне (val dom auc 0.5348).
λ исключена: за эпоху 0 она не превышает 5e-4 (достигает этого в самом конце), а
эталонный прогон 261002_0535 при той же программе λ в тот же момент имел
val dom auc 0.6948.

Задача игры (MC ν+μ с половинным z-флипом против exp с зеркалом), одни и те же
замороженные фичи эпохи 0:

| читатель | AUC |
|---|---|
| живой критик из чекпойнта (eval) | 0.5302 |
| тот же линейный критик, обученный offline по рецепту игры (15 625 шагов) | 0.6096 |
| то же, 62 500 шагов | 0.6219 |
| свежий logreg (3-fold, стандартизация) | 0.6400 |
| MLP [32,16] без LN | 0.7339 |
| **MLP [32,16] + LN (критик эталона)** | **0.7624** (62 500 шагов: 0.7887) |

Живой критик теряет ~0.08 против того же рецепта на замороженных фичах — это цена
движущегося представления внутри эпохи 0. Остальное — линейность: доменный сигнал в
представлении маленькой модели существенно нелинейный, линейному читателю доступен
потолок ~0.62-0.64. Проба тренера (μ против exp) воспроизведена с точностью 1e-4
(0.6754 против 0.6753 в логе) — протокол извлечения фич верен.

Вывод: расхождение с эталоном (0.695 в конце эпохи 0) — линейность критика, не λ.
Перезапуск: `261010_1755_..._small_d64_l2` с критиком как в эталоне.

Запуск: `python inference/nu_classifier/analysis/small_model_critic_diag/diag_epoch0_critic_ceiling.py`
(фичи кэшируются в `epoch0_feats.npz`, в git не попадает; конфиг берётся из снимка
внутри каталога прогона).

## Почему auc_game_all (0.726) выше auc_all (0.670) — разложение

Задача игры отличается от исторической пробы двумя вещами сразу: на стороне MC
добавлены ν и включён z-флип-протокол. `decompose_game_vs_hist.py` (чекпойнт
261010_1755, конец эпохи 3; свежий logreg, 3-fold, образец пробы) воспроизводит оба
числа из лога и раскладывает разницу:

| срез | AUC |
|---|---|
| A. μ vs exp, чистое (= `auc_all`) | 0.6703 |
| B. μ vs exp, обе стороны зеркальны | 0.6642 |
| C. ν vs exp, чистое | **0.9934** |
| D. ν vs exp, зеркало | 0.9919 |
| E. MC(μ+ν) vs exp, чистое | 0.8261 |
| F. MC vs exp, протокол игры (= `auc_game_all`) | 0.7255 |

Вклады: **+0.156 от добавления ν** (exp — реальные мюоны, ν — другой класс: классовая
ось работает против exp) и **−0.101 от протокола игры**. При этом зеркалирование само
по себе почти ничего не стоит (B−A = −0.006, D−C = −0.002) — стоит *смешение
ориентаций* внутри каждой стороны: половинный флип источника и удвоение цели дают
под-облака, для которых одному линейному направлению приходится идти на компромисс.
Следствие: `auc_game_all` — честное число для сравнения с `Val dom` (та же задача), но
это не чистый метр доменной инвариантности — он тяжёло смешан с классовым содержанием
(ν-половина). Чистый метр остаётся μ-only (`auc_all`).

## Проверки числа ν-vs-exp ≈ 0.99 (verify_nu_vs_exp.py)

После сомнения владельца («не верю в такую точность, наверное баг»): баг нашёлся, но в
самой проверке — реконструкция укладки кэша применяла размер батча источника (512) к
цели (у неё 256), «чистый exp» собирался наполовину из зеркальных копий. После починки
якорь воспроизводится точно: μ-vs-exp = **0.6611** (как в первом дневнике). Числа:

| проверка | AUC |
|---|---|
| ν vs exp, натуральный состав, независимый путь (другой чекпойнт) | **0.9994** |
| ν-нат vs exp-нат, подблоки пробы | 0.9999 |
| ν весь vs exp весь (= C, обогащённый образец) | 0.9934 |
| ν-хвост vs exp-хвост (самая похожая пара) | 0.9771 |
| сырые скаляры без модели: суммарный заряд / макс. заряд / число хитов | 0.686 / 0.625 / 0.671 |
| *справка:* сырые скаляры μ-vs-exp | 0.593 |
| юнит-проверка `_probe_embeddings(flip_z=True)` против ручной реализации | max diff 0.00e+00 |

То есть 0.99 — не артефакт: натуральный состав даёт 0.999, обогащение хвостом его даже
занижает. Объяснение — классовое содержание: сравнение идёт MC-ν против всего пула exp
(мюонного; хвост exp — перепутанные мюоны, см. `group_structure_result`), а классовая
задача ν-vs-μ = 0.9999. Это не «MC-ν против данных-ν» — данных-ν в образце единицы.
Флип классовую ось не трогает: под зеркалом ν остаётся ν.

## «Честная» задача владельца: {exp + exp_flip} vs {nu + nu_flip} (honest_class_separation.py)

Классы содержат обе ориентации, признак направления нейтрализован. Обучение и тест
(grouped-CV по событиям; фичи — кэш probe_emb_latest.npz, чекпойнт 261010_1755):

| задача | модель | AUC |
|---|---|---|
| {exp+flip} vs {ν+flip} | logreg, 3-fold grouped | **0.8329** |
| {exp+flip} vs {ν+flip} | MLP [32,16]+LN, grouped тест 80/20 | **0.8684** |
| ν чистые vs exp зеркало (напр. выкл.) | logreg | 0.8926 |
| ν зеркало vs exp чистые (напр. выкл.) | logreg | 0.8805 |
| ν чистые vs exp чистые (напр. вкл.) | logreg | 0.9934 |
| ν зеркало vs exp зеркало (напр. вкл.) | logreg | 0.9919 |
| натуральные подгруппы, напр. выкл. | logreg | 0.8572 / 0.8413 |
| контроль без модели: суммарный заряд (флип-инвариант) | — | 0.6858 |

Читать: 0.99 в C/D — это признак **направления** прилёта (в проекте установлено:
«сеть — детектор направления»), а не классовое содержание. Честная задача с
нейтрализованным направлением читается на 0.83-0.87 — не идеально (правота владельца),
но и не 0.5: остаток реален и виден уже на сыром заряде (exp ярче ν: медианы 37 против
23 п.е.; AUC 0.69) — разница отклика/содержимого, не зеркало. Квадрант «ν зеркало vs
exp зеркало» = D из decompose_game_vs_hist (0.9919 — в точности).

Ошибки этого замера (все пойманы якорями; для истории): список булевых масок вместо
массива (пул-строка считалась как дублированный квадрант); сдвиг индексов 2*n_exp в
тестовой маске MLP (тест из одного класса → nan); в предыдущей проверке — размер
батча цели 256 вместо 512.

## Полная задача игры в честном протоколе (обе ориентации в каждой стороне)

Переделано 2026-10-10 по запросу владельца: каждый элемент таблицы — разделение сторон,
в каждой из которых события присутствуют в ОБОИХ крыльях (чистое + зеркальное),
обучение и тест (grouped-CV по событиям, MLP — grouped 80/20). Фичи — probe_emb_latest.npz.

| задача | logreg | MLP [32,16]+LN |
|---|---|---|
| {μ + μ_flip} vs {exp + exp_flip} | 0.6494 | — |
| {ν + ν_flip} vs {exp + exp_flip} | 0.8335 | 0.8684 |
| **{μ + ν, обе} vs {exp, обе} — ЗАДАЧА ИГРЫ** | **0.7265** | **0.7749** |
| то же, по одному представлению на событие (как в тренере) | 0.7222 | — |
| *для континуитета, старые одноориентационные:* μ vs exp чистое | 0.6703 | — |
| *MC vs exp чистое (старый E)* | 0.8261 | — |
| *старый протокол F (тренера)* | 0.7255 | — |
| *сырой заряд, без модели* | 0.6858 | — |

Чтения: μ-часть к честному флипу почти равнодушна (0.670 → 0.649) — направление и не
было её признаком; ν-часть падает 0.99 → 0.83/0.87 — направление было её признаком;
полная задача (0.73/0.77) НИЖЕ ν-части в одиночку: единому направлению приходится идти
на компромисс между μ- и ν-частями, нелинейный читатель возвращает часть (0.775).
Три конструкции протокола (обе ориентации / по одному представлению / протокол тренера)
сходятся у 0.72-0.73 — число устойчиво. Живой критик прогона в этой же задаче: 0.53-0.70
по эпохам — в лучшем (эпоха 0: 0.70) близко к потолку свежего logreg (0.73), но ниже
MLP-потолка (0.775) уже с рождения.

Ошибка этого прогона: строка «MLP» сначала посчиталась logreg'ом (не прокинут параметр
model в both_orientations) — исправлено, таблица выше — после починки.
